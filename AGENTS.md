# Working in this repository

Instructions for every coding agent (Claude Code reads this through `CLAUDE.md`; Codex
reads it directly) and the short version of the rules for people. `README.md` is the
picture of the system; `docs/DEVELOPING.md` is the long form of how it is built. When
this file and the code disagree, the code is right and this file is fixed in the same
change.

## What Sprout is

An iOS health coach: SwiftUI + SwiftData, mirrored to the user's private iCloud database,
plus one small server: the AI gateway in `server/`, which holds the API keys so nobody using
the app needs one (App Attest, a daily allowance per phone). The project is generated by
xcodegen from `project.yml`; the targets are `Sprout*`. The bundle id, iCloud container,
App Group and other stored identifiers keep the `com.bryanram.victoria` names the app
shipped under and must never be renamed (an update would install as a different app and
leave the data behind). The repository is public and doubles as the
owner's AI-engineering portfolio, so a claim in the README or the docs is measured or
live-verified, never estimated silently.

## Where the repository lives

`~/dev/GitHub/sprout`. **Never work from a copy under `~/Documents`**: that folder is

## How we build anything (the method; `docs/DEVELOPING.md` has the long form)

1. **Research the standard first.** Find how the established work does it (Apple's
   documentation, the provider's API reference, the published dataset or paper) before
   designing. Write what you found into the EVAL_REPORT section.
2. **Make no assumptions; verify empirically.** Read the code that runs, run it, look at
   the output. A surprising result is re-run before it is recorded.
3. **Measure alternatives side by side.** A model, a prompt or a threshold is chosen by
   running the candidates on the same labelled cases (`Evals/`), with accuracy, cost,
   tokens and latency per candidate. The cheapest candidate within the noise of the best
   is the default.
4. **Test every path you can think of**, including the regression check that the existing
   path is unchanged. Time is injected (a date, a calendar, a zone), never read from the
   wall clock inside logic under test.
5. **Record every number.** Results go in `docs/EVAL_REPORT.md` (next free section number),
   one row per test file in `SproutTests/LEDGER.md`, a version's test evidence in
   `docs/test-evidence/<label>/` (`tooling/evidence/capture.sh`), every live evaluation in
   `Evals/runs/`, and the change itself in `CHANGELOG.md`.
6. **Be honest.** Verified is verified; read-but-not-run is said to be that; "done" means
   tested and recorded.

## Gates: all green before a push, and CI runs them again

- `xcodegen generate` (after adding or moving ANY file; sources are globbed)
- the unit suite, with the count read from the result bundle (`tooling/check_xcresult.py`)
- the `SproutEvals` scheme (offline self-tests of the graders and datasets)
- a Release build
- `gitleaks git --redact .`

`tooling/evidence/capture.sh <label>` runs all of them and writes the record.

## Conventions that are easy to miss

- **Every model call names its task.** A call site passes `AIConfig.model(for: .<task>)`
  from `AITask`; it never names a model or a tier. A new AI feature adds a case to
  `AITask`, a row to `AITaskModelTests`, and an evaluation.
- **A default model changes only with a measurement.** A row in
  `AIConfig.measuredDefaults` cites the EVAL_REPORT section that measured it, and a test
  refuses a row that does not.
- **New AI features go through `AIClient.make()` / `makeFull()`**, never a vendor client
  constructed at a call site, and gate on `AIConfig.hasActiveKey` with a template or
  manual fallback.
- **The AI layer speaks Anthropic's wire vocabulary internally;** other providers
  translate at the client boundary (`Services/AI/`). What an OpenAI model needs
  (endpoint, token parameter, reasoning effort) is decided in `OpenAIModelProfile.resolve`
  and nowhere else.
- **Tests never reach a provider.** Client behaviour is tested through `AIRuntime` with a
  `ScriptedTransport`. Only `Evals/run.sh` makes a paid call, and only when asked.
- **Nothing paid without the owner's approval in the session.** A live evaluation states
  its estimated cost first.
- **Every ingest path goes through the pure, unit-tested merge functions** (idempotent
  upserts); a new data source reuses them and never writes parallel insert logic.
- **Nothing opt-in leaves the device without the opt-in.** A buddy snapshot is built
  through `BuddySnapshotPayload.init`, which blanks the full-stats fields unless the user
  shared them (EVAL_REPORT 3, D-V1).
- **Prompts, demo and seed content are variant-aware:** no hardcoded name, pronoun or
  goal direction (EVAL_REPORT 3, A-1 lists the prompts that still break this).
- **Datasets are immutable once a result cites them.** A change is `v<n+1>.jsonl`.
- **Git:** one branch per change (`<owner>/<topic>`), commits in plain sentences, no
  `Co-Authored-By` line and no mention of AI or an assistant in commits or PR bodies. The
  owner merges.
- **Secrets:** never type, paste or print an API key. Evaluations read keys from the
  environment; the owner enters keys in the app himself
  (`xcrun simctl pbsync host <UDID>` moves the Mac clipboard to the simulator unread).
- **CloudKit Production schema and TestFlight uploads are the owner's actions.**

## Build & test

```bash
xcodegen generate                       # after adding/moving ANY file (sources are globbed)
xcodebuild test -project Sprout.xcodeproj -scheme Sprout \
  -destination 'platform=iOS Simulator,name=Sprout-Dev' \
  -resultBundlePath /tmp/t.xcresult
# NEVER trust the pipe's exit code — read the counts out of the bundle:
python3 tooling/check_xcresult.py /tmp/t.xcresult --min-tests 1231
# The evaluation harness's offline self-tests (its own scheme; 3 live evals skip without a key):
xcodebuild test -project Sprout.xcodeproj -scheme SproutEvals \
  -destination 'platform=iOS Simulator,name=Sprout-Dev' -resultBundlePath /tmp/e.xcresult
```

- Sim: **Sprout-Dev** (iPhone 17 Pro, iOS 26.4). Address it by name; the UDID changes whenever the
  simulator is recreated (`xcrun simctl list devices | grep Sprout-Dev`). If it is missing:
  `xcrun simctl create Sprout-Dev "iPhone 17 Pro" com.apple.CoreSimulator.SimRuntime.iOS-26-4`.
- Install gotcha (FinderInfo detritus): before `simctl install`, run
  `xattr -cr "$APP" && codesign --force --deep --sign - "$APP"`.

## Driving the simulator UI (screenshots, tap-throughs)

The runner is an XCTest HTTP server on **:22087** from the `ios-agent_automation` repo.

```bash
cd ~/Documents/GitHub/ios-agent_automation
bash scripts/start-sim-runner.sh --udid <UDID of Sprout-Dev>   # background it
# ⚠️ The flag is --udid. `UDID=` / no flag silently falls back to a DIFFERENT default sim
#    (it will boot iPhone 17 Pro, shut nothing down, and you'll drive the wrong device —
#    symptoms: fresh-install onboarding screen, wrong timezone, "where did the data go").
```

Drive it with the CLI directly (works even when the ios-tester MCP tools are gone):

```bash
node ios-exec.mjs --udid <UDID> --steps '[{"tapText":"Settings"},{"sleep":1},{"screenshot":true}]'
```

- Verbs: `tap:[x%,y%]`, `tapText`, `type` (needs a FOCUSED field — tap it first),
  `replaceText:["Label","value"]`, `swipe:[x1,y1,x2,y2]`, `scroll`, `waitText`,
  `hierarchy` (labels + % coords), `screenshot`, `launch`, `eraseText`, `key`.
- Chat send button sits at ~`[91,58]` with keyboard up; message field ~`[50,87]` without.
  Typed sends can land DELAYED — check the transcript before retyping (double-send risk).
- SpringBoard alerts aren't in the app hierarchy — tap by % coordinates.
- Keyboard covers buttons; dismiss by scrolling the list or cold-restarting the app.
- `open -a Simulator --args -CurrentDeviceUDID <UDID>` if the window isn't visible
  (headless boot is common after runner restarts).

## Demo profiles & the two variants

```bash
xcrun simctl launch <UDID> com.bryanram.victoria --seed-demo               # light theme, loss goal
xcrun simctl launch <UDID> com.bryanram.victoria --seed-demo --demo-gain   # dark theme, lean-gain
# also: --demo-fueled, --demo-tab <food|progress|coach|workouts>, --demo-screen <workout|achievements|buddy>
# (--demo-tab workouts opens Gym mode; the others open that tab in Home mode)
# on the Nutrients tab (with --demo-tab food): --demo-scroll-nutrients, --demo-food-detail <name>,
#   --demo-food-edit <name> [--demo-scroll-label]; --demo-no-notification-prompt for a screenshot run
# the coach chat, DEBUG only (Sprout/Features/Coach/CoachDebug.swift has the full list):
#   --demo-long-chat <n>        replace the conversation with n seeded messages
#   --chat-probe                log load time and memory to tmp/chat-probe.log in the data container
#   --chat-debug-script <name>  answer the coach from a canned script (ok, tool, confirm, flaky, 401, 429, …)
#   --no-notification-prompt    skip the permission alert (a screenshot run cannot tap it away)
```

- Seeding only happens when no profile exists. To reseed: terminate app, then delete the
  store — it lives in the **app group** container:
  `…/Containers/Shared/AppGroup/<id>/Library/Application Support/default.store*`
  (back it up first; also delete the `dailyBrief.v1` key from the app's Preferences plist
  or yesterday's cached brief survives).
- **Keychain survives store wipes**: Google Health OAuth tokens + AI keys persist, so the
  Fitbit connection auto-heals into a fresh profile on next launch. UserDefaults
  (client ID, provider choice) also survive — only SwiftData rows reset.
- `simctl spawn <UDID> defaults` CANNOT reach the app's preferences domain — edit the
  plist in the app container with PlistBuddy (app terminated first, or cfprefsd
  resurrects the old values).

## Secrets & live testing

- NEVER type/paste API keys or handle the user's credentials — Bryan enters keys himself
  (sim clipboard: `xcrun simctl pbsync host <UDID>` moves his Mac clipboard over unread).
- AI provider/model checks: Settings → AI Provider → "Verify key works" pings the
  DEFAULT coach model live. Per-call token usage (`in/out/cached`) is in hidden
  Diagnostics: Settings → tap the version line 7×. The store is directly inspectable:
  `sqlite3 -readonly ".../default.store"` (dates are Apple epoch: +978307200).
- OpenAI prompt-cache verification needs ≥60s between calls (write → readable lag);
  back-to-back `cached 0` is not a failure signal.

## Conventions

- Every ingest path goes through pure, unit-tested merge functions (idempotent upserts);
  new data sources reuse them — never write parallel insert logic.
- The AI layer speaks Anthropic's wire vocabulary internally; other providers translate
  at the client boundary (`Services/AI/`). New AI features go through `AIClient.make()`/
  `makeFull()` — never construct a vendor client at a call site (grep for stragglers
  when adding provider features; `PlanService.review()` was missed once).
- Every optional AI feature gates on `AIConfig.hasActiveKey` (not the Anthropic-only
  `KeychainStore.hasAPIKey` shim) and has a template/manual fallback.
- Demo/seed content must be variant-aware — no hardcoded names or goal-direction copy.
- Claims in README/docs must be measured or live-verified, never estimated silently.
